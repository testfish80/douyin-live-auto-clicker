# 抖音直播间双间隔自动点击器

一个在浏览器控制台运行的悬浮面板小工具：按你设定的两个间隔，循环点击页面上同一个目标按钮。默认目标是抖音直播中控商品列表里的第一个按钮，适合在你自己的直播间里做定时、轮换类的辅助操作。

> 本工具只在你自己的浏览器里运行，不上传任何账号、页面数据；是否合规取决于直播平台的规则，使用前请先确认平台规则，并对点击目标负责。

## 文件说明

- `auto-clicker.js`：完整工具代码，复制后粘贴到浏览器控制台即可运行，页面刷新后需要重新粘贴。

## 使用方法

1. 在抖音直播中控页面打开浏览器开发者工具的控制台（Console）。
2. 把 `auto-clicker.js` 的全部内容粘贴进去并回车，页面右上角会出现一个悬浮面板。
3. 点击面板上的「🎯 拾取目标元素」，再点击页面上你真正想点的那个按钮，面板会自动填入它的 XPath；也可以直接在输入框里手动改 XPath。
4. 设置两个间隔：
   - 间隔 1：第一次点击后等待的秒数，默认 1 秒；
   - 间隔 2：第二次点击后等待的秒数，默认 3 秒。
5. 点「启动循环」，面板状态栏会显示当前轮次和剩余等待时间；点「停止」或面板右上角的 × 即可结束。
6. 面板标题栏可以拖动，换个不挡按钮的位置。

## 循环逻辑

每轮固定是两步：

1. 点击目标一次；
2. 等待间隔 1；
3. 再点击目标一次；
4. 等待间隔 2；
5. 进入下一轮，直到手动停止。

## Worker 定时说明

本工具的等待不是直接用主线程 `setTimeout`，而是用一个 Web Worker 每 200 毫秒发一次心跳，主循环等到心跳再扣 0.2 秒。这样做的好处是：标签页切到后台后，主线程定时器容易被浏览器节流，Worker 心跳相对更稳，间隔不容易被拖得很长。

有两点需要说明：

- Worker 里只有计时，不能操作页面，点击本身仍在主线程按 XPath 执行；
- 如果浏览器把标签页彻底挂起、丢弃，或者页面 CSP 拦截了 blob Worker，定时还是会停或回退到普通定时，不是绝对不受后台影响。出现回退时，状态栏会提示「Worker 被拦截，已回退普通定时」。

## 使用前必须确认的事

- **先确认按钮的含义**：很多按钮是开关式的，点一下是开始、再点一下是取消。比如商品讲解按钮，点两次可能等于刚开始讲解就取消，观众端只会闪一下。请先在页面上手动点一次，看清按钮文案和状态变化后再用自动循环。
- **间隔别设太短**：秒级的连续点击不适合讲解类场景，讲解一个商品通常要讲几分钟；间隔请按实际讲解时长来设，不要用默认的 1 秒、3 秒直接跑讲解。
- **XPath 很脆弱**：页面结构、商品排序、展开收起一变，定位就可能点错或点不到。每次开播前请重新拾取一次目标，不要直接沿用上次的 XPath。
- **不要无人值守依赖它**：本工具没有状态校验、没有失败重试、没有异常兜底，页面一刷新脚本就消失，平台也可能对自动化操作有限流、断播等处理。建议把它当作助播提醒的辅助，而不是完全无人化的方案。

## 停止方法

- 点面板上的「停止」，最多等一拍心跳（200 毫秒）后循环干净退出；
- 点面板右上角的 ×，同样会结束循环并移除面板；
- 直接刷新页面，脚本和面板都会消失。
